
# RecoverAI — Final Submission Project

RecoverAI is an AI-powered revenue recovery platform for failed payments.

## What is included

- Responsive merchant dashboard
- Failed transaction management
- Recovery queue
- Recovery probability prediction
- ML model (Random Forest)
- Synthetic training dataset generator
- SQLite transaction database
- FastAPI backend
- Demo payment failure generator
- Recovery action endpoint
- Razorpay webhook endpoint with optional signature validation
- Docker deployment configuration
- Render deployment configuration

## Run locally — Windows

Open the project in VS Code.

### 1. Create environment
```powershell
python -m venv venv
venv\Scripts\activate
```

If PowerShell blocks activation:
```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
venv\Scripts\activate
```

### 2. Install dependencies
```powershell
pip install -r backend\requirements.txt
```

### 3. Train the model
```powershell
python ml\train_model.py
```

This creates:
- `data/transactions.csv`
- `ml/recovery_model.pkl`

### 4. Start the server
```powershell
uvicorn backend.main:app --reload
```

### 5. Open the project
http://127.0.0.1:8000/app

API docs:
http://127.0.0.1:8000/docs

Health:
http://127.0.0.1:8000/api/health

## Demo flow for judges

1. Open `/app`.
2. Click **Create Demo Payment**.
3. A failed payment is created and stored in SQLite.
4. The ML model predicts recovery probability.
5. Click **Analyze** to show the AI explanation.
6. Click **Recover Payment** to schedule recovery.
7. Open **Recovery Queue** to show prioritized opportunities.
8. Open **Analytics** to present business impact.

## Razorpay Test Mode

Use Razorpay Test Mode only for the hackathon demo. Test mode uses separate test credentials and does not process real payments.

After deployment, configure the Razorpay Test Mode webhook:
`https://YOUR-DOMAIN/api/webhook/razorpay`

Set the `RAZORPAY_WEBHOOK_SECRET` environment variable on the server.

Never commit API secrets to GitHub.

## Deployment

This repo includes `Dockerfile` and `render.yaml`.

A deployment service can build the container and expose:
`https://YOUR-DOMAIN/app`

The public URL is generated by the hosting provider after deployment. This chat environment cannot create an external hosting account or publish a URL on your behalf without access to your hosting account.
